## 1. 业务目标 / 業務要件

### 1.1 目标

让报告者在实际工作上下文中记录问题，让处理者管理复现与修复，让验证者独立确认结果，并使 Project 成员在授权范围内看到缺陷风险、趋势和待办。智能辅助减少信息整理、重复检查与验证准备的工作量，所有建议均可追溯到可读取的证据及版本。

目标业务结果：一条缺陷从提交到关闭具有稳定身份、责任人、变更历史和验证结论；任何人打开它时都能了解当前状态、下一步、关联任务与可访问证据。效果指标以真实运行记录建立基线，不能以本文的设计目标声称已达成。

### 1.2 适用人员

| 角色 | 主要责任 | 能力控制 |
|---|---|---|
| 报告者 | 创建和补充现象、重现步骤与附件 | 创建、查看及对允许字段补充；可收到验证请求。 |
| 分诊者 | 去重、确认范围、严重度、优先级、分派与退回 | 分诊、关联、修改责任人及配置允许的流转。 |
| 处理者 | 重现、关联修复任务及提交修复依据 | 在获授权 Lane/Worktree 中处理并提交验证。 |
| 验证者 | 依据固定版本和测试证据独立验证 | 接受或驳回验证；独立性由策略和实际执行身份验证。 |
| Project 管理者 | 设置工作流、分类、通知和统计口径 | 配置权限和生效版本，不自动获得其他 Project 数据。 |
| Agent / Worker | 在授权范围内整理证据、提出建议或执行已授权任务 | 绑定主体、能力、预算与策略；每次执行重新授权，输出和操作可审计。 |

角色是业务职责，部署可通过授权策略组合；服务端逐命令校验能力及资源范围。

### 1.3 模块位置与范围

主导航保持 `Project → Lane → Worktree → Branch`。选中 Worktree 后，在该 Lane 的 **Backlog/Sprint** 中打开“缺陷”视图；缺陷卡在同一可关闭任务详情窗口打开，CLI 继承当前已授权 Worktree。Branch 下的缺陷任务按工作流状态分组。没有 Worktree 的 Lane 可在其既有独立任务入口记录和查看已授权缺陷，尚无 checkout 的记录标记为未绑定，执行与完整 Lane App tabs 仍遵守现有入口条件。

Project Worktree Index / Project 级缺陷汇总只展示当前主体有权访问的跨 Lane 投影，可定位回来源 Lane。汇总不改变记录 owner，也不替代主导航。Canvas、Workflow/LangGraph、BI 和 Plugins 通过同一 Lane 上下文引用缺陷。缺陷详情、修复任务、验证证据和通知使用同一业务身份，不复制出第二套权威缺陷列表。

本期范围包括手工与授权来源建卡、列表、详情、缺陷生命周期、证据、独立验证、智能建议、通知和质量报表。外部问题系统导入或双向同步列为后续可选连接能力，需另行定义连接授权、许可、字段映射、来源身份和冲突策略，不作为本期闭环前提。

## 2. 术语、业务规则与流程

| 术语 | 业务含义 |
|---|---|
| 缺陷 | 观察到或可验证的实际结果与预期不一致，以 `Bug` 类型 WorkItem 承载；补充字段及其版本由该业务事实 owner 管理。 |
| 现象 | 可观察的失败表现；一条报告可以包含关联现象，也可在分诊时拆分。 |
| 原因 | 经证据确认的根本原因；一项原因可对应多个现象，一个现象也可能涉及多个原因。未确认时为未知。 |
| 严重度 | 对业务、数据、安全或可用性的影响程度，与排期优先级独立。 |
| 优先级 | 在明确的工作范围内安排处理顺序，由授权人员结合影响和约束决定。 |
| 验证记录 | 指向修复版本、执行身份、测试范围、结果与证据的有版本事实。 |
| 智能建议 | 针对固定输入版本和可追溯证据生成的候选结论，保留不确定性和来源。 |

默认流程为 `待分诊 → 已确认 → 处理中 → 待验证 → 已关闭`。分诊可产生 `待补充`、`重复` 或 `不处理` 等结果；验证失败进入 `重新打开` 并返回处理。默认状态及字段约束可由授权 Project 管理者配置版本化策略，使用中记录保留生效版本。处理完成、验证通过和关闭为可区分的业务事实。现有任务卡生命周期与缺陷工作流必须在基本设计中定义完整映射，包含历史记录迁移、未知状态、回退与冲突；无法映射时禁止静默改写。

### 2.1 默认分级和流转条件

下列默认值作为首版策略建议，各 Project 可经授权配置。严重度描述实际影响，优先级描述处理顺序，两者不互相推算。

| 严重度 | 默认判定 |
|---|---|
| S1 严重 | 核心服务不可用、数据损坏或重大安全影响，且影响范围已确认。 |
| S2 高 | 主要业务能力受阻或大范围功能异常，存在有限绕行方式。 |
| S3 中 | 局部功能异常，有可行绕行方式，核心流程仍可使用。 |
| S4 低 | 低影响的显示、文案或边缘问题。 |
| 未确认 | 信息不足以判断；保留该状态并列出所需证据。 |

优先级默认为 P0 紧急、P1 高、P2 普通、P3 低和未排定。负责人、验证者、环境和复现信息在创建时可缺省；进入后续状态的必填条件由生效策略决定。建议发现阶段包含需求、设计、实现、单元测试、集成测试、系统测试、发布后和未知，并保留用户配置的扩展项。

| 操作 | 起点 → 目标 | 默认条件与结果 |
|---|---|---|
| 提交 | 草稿 → 待分诊 | 标题及现象非空，记录报告者、范围和首个 revision。 |
| 请求补充 / 补充 | 待分诊 ↔ 待补充 | 记录缺失项；补充后保留原报告及操作历史。 |
| 确认 | 待分诊 / 重新打开 → 已确认 | 授权分诊者确认现象、影响或保留未知字段，设置下一责任人。 |
| 开始处理 | 已确认 / 重新打开 → 处理中 | 授权处理者领取或分派；需要 checkout 的操作要求有效 Worktree 绑定。 |
| 提交验证 | 处理中 → 待验证 | 固定修复标识与待验证范围，关联对应修复证据。 |
| 验证通过并关闭 | 待验证 → 已关闭 | 授权验证者在指定版本完成独立验证，满足必填和阻塞关系检查。 |
| 验证失败 / 再次发生 | 待验证 / 已关闭 → 重新打开 | 记录失败或再现证据，原验证记录和关闭历史可追溯。 |
| 标记重复 / 不处理 | 待分诊 / 已确认 → 终结结果 | 授权人员记录原因；重复须关联有权读取的目标，原始报告保留。 |

终结后的关系修正或再次处理需要授权及新版本命令。批量操作中每条记录独立验证以上条件。

## 3. 功能要件 / 機能要件

优先级 P0 为首个可信业务闭环，P1 为完整团队协作，P2 为后续增强。各项目标状态均为 `未验收`。

### 3.1 创建、归属和列表

| ID | 优先级 | 要件 |
|---|---|---|
| FR-DI-001 | P0 | 在 Lane 的任务管理中提供缺陷列表与创建入口，并以 `Bug` WorkItem 的稳定 ID 贯穿树、看板、详情、搜索和 BI。 |
| FR-DI-002 | P0 | 创建时记录 Project、Lane、报告者和授权上下文；可绑定 Worktree/本地 Branch。没有 checkout 的 Lane 可保存未绑定记录，所有绑定须验证同一 Project、Lane 归属及当前权限。 |
| FR-DI-003 | P0 | 新建表单包含标题、现象描述、预期结果、实际结果、重现步骤、影响范围、发现阶段、严重度、优先级、环境及附件。标题和现象为提交必填；重现信息不足允许明确标记“待补充”，具体条件由生效工作流决定。 |
| FR-DI-004 | P0 | 列表按授权范围服务端分页，支持状态、严重度、优先级、负责人、报告者、Lane、Worktree、Branch、版本、标签、发现阶段、时间及文本筛选，支持稳定排序和可配置列。 |
| FR-DI-005 | P1 | 用户可保存个人查询，获授权者可发布 Project 范围共享查询；查询本身、结果和关联计数均受当前权限过滤。 |
| FR-DI-006 | P0 | 展示数据来源、当前范围及加载/空/未连接/无权限/失败状态；授权缺失或来源不可用时禁止将缓存、预览或示例数据显示为当前生产事实。 |
| FR-DI-007 | P1 | 支持批量修改、分派和状态操作，先预览目标与权限、版本冲突和结果；逐条返回成功、拒绝或未知，不对部分失败伪称整体成功。 |

### 3.3 分诊、修复和验证

| ID | 优先级 | 要件 |
|---|---|---|
| FR-DI-015 | P0 | 分诊者可确认、退回补充、分派、设置严重度与优先级，并在授权和版本一致时记录理由。 |
| FR-DI-016 | P0 | 状态流转按工作流版本、角色与字段要求校验；不满足条件时返回可理解的阻断原因。 |
| FR-DI-017 | P0 | 修复可关联已有任务卡或创建绑定缺陷的修复任务；任务执行实例与缺陷是不同事实，执行取消、失败或完成均不能自行证明缺陷已修复。 |
| FR-DI-018 | P0 | 处理者提交待验证时固定修复标识、范围与证据，验证者依据相同版本记录通过/失败、测试方法及证据；修复者与验证者的独立性由策略强制，例外须显式记录授权理由。 |
| FR-DI-019 | P0 | 关闭前检查所需验证、阻塞关系、必填字段和当前权限；未满足条件拒绝并列出原因。验证失败或关闭后再次发生时可重开并保留原历史与证据。 |
| FR-DI-020 | P0 | 修改使用 owner revision/CAS 与幂等命令。冲突返回最新版本与可恢复草稿；结果未知时按同一操作身份查询回执或经用户确认重试，禁止授权失败后自动重放。 |

### 3.4 智能辅助

| ID | 优先级 | 要件 |
|---|---|---|
| FR-DI-021 | P1 | 根据用户选定且有权读取的报告、日志和附件提出标题、摘要、重现步骤、影响范围及缺失信息的草稿；标记来源、缺失与不确定性。 |
| FR-DI-022 | P1 | 根据授权范围内的历史缺陷给出重复或关联候选，展示匹配依据与可读取证据；不可泄露无权记录的标题、摘要、计数或存在性。 |
| FR-DI-023 | P1 | 建议严重度、优先级、分类、负责人和处理顺序时展示规则依据、证据及置信信息的含义；未经校准的分数不得表示为可靠概率。建议由授权主体采纳、修改或拒绝并记录。 |
| FR-DI-024 | P1 | 基于授权文件、变更及验证记录提出可能原因、影响范围、修复步骤和回归测试建议；缺少证据时明确未知。建议不能自动写入最终原因或验证结论。 |
| FR-DI-025 | P1 | 智能建议固定输入对象 revision、证据摘要、模型/provider/profile 版本、策略和生成时间。输入变更、权限撤销或策略更新后标为过期并重新授权；采纳前核对版本。 |
| FR-DI-026 | P1 | 允许有权限的用户从缺陷启动受控 Agent 工作流。执行必须绑定 Run/Worktree/Task、当前身份、原生 Hook、资源预算与 sandbox，支持取消、恢复、有限输出和独立验证。缺少执行条件时禁用并说明原因。 |
| FR-DI-027 | P1 | 未授权内容不得送入模型；输入采用最小必要范围，外部 provider 必须符合项目策略和数据边界。对附件或日志中的指令按不可信内容处理，模型输出经结构与权限校验。 |
| FR-DI-028 | P1 | 记录建议的生成、查看、采纳、修改、拒绝与后续结果；提供人工纠正和停止能力。推理失败、超时或预算耗尽时保留缺陷草稿，手工流程仍可使用。 |

### 3.5 通知、质量分析与治理

| ID | 优先级 | 要件 |
|---|---|---|

### 5.2 接口与授权

- UI 使用已有授权会话、Lane/Worktree 上下文与 WorkItem 接口，服务端重新校验 Project/Lane、对象、动作和当前策略。401 使会话能力失效，403 只表示该资源/动作被拒绝。请求必须携带期望版本及适用幂等身份。
- 与验证、附件、代码版本、通知和 BI 的交互通过各自 owner 的版本化契约，返回明确的授权、不可用、冲突、结果未知与可重试状态。
- 任务、协作和通知事件通过 owner 事务 Outbox/Inbox 传递。传输 provider 固定版本/profile 身份，重试不跨 provider 比较游标或复用去重窗口。
- 文件和证据访问采用最小 scope、可审计桥接；执行组件使用受控工具和沙盒，不向 Agent 暴露任意宿主 shell、数据库凭据或 Multipass socket。
