## 2. 关键设计决策合理性评估

| 决策点 | 当前选择 | 合理性 | 潜在顾虑 | 缓解措施 |
|--------|----------|--------|----------|----------|
| **持久化: Git FS 主 + SQLite 索引** | ✅ 合理 | Git 原生版本控制、分支/合并/同步/审计零成本；SQLite 仅加速查询 | 大仓库 registry.json 读写性能 | SQLite 索引异步更新；分页查询；可选 PG 归档 |
| **目录结构: 按文件分层** | ✅ 合理 | 语义清晰、CodeLens/TreeView 直接映射、Git diff 可读 | 深层路径过长 (Windows 260 限制) | 文件路径 hash 缩短目录名；或配置 `short_path = true` |
| **Agent 适配: 插件 + 内置 4 个** | ✅ 合理 | 覆盖主流 95% 场景；WASM 扩展开放生态 | Adapter 版本兼容性维护成本 | 版本检测矩阵 + 降级基础模式 + 语义化版本 |
| **上下文: 增量 checkpoint + artifact store** | ✅ 合理 | 平衡存储/恢复速度；大文件走 LFS/S3 | Checkpoint 丢失导致无法恢复 | 双写 (本地 + 可选 S3)；Git commit 即备份 |
| **分支策略: 可选 worktree 隔离** | ✅ 合理 | 并行隔离原生支持；可配置开关 | Worktree 数量过多性能下降 | 限制并发 worktree 数；定期清理归档 session |
| **Task Card 关系: 可选双向链接** | ✅ 合理 | 正交解耦；用户自主选择关联 | 双向链接数据一致性 | 应用层事务保证；单向引用为主 |
| **REST API: 新建 /file-sessions** | ✅ 合理 | 资源模型差异大；RLS 独立演进 | 客户端需维护两套 API | OpenAPI 统一生成 SDK；文档明确区分 |
| **前端: 三端全覆盖** | ✅ 合理 | CLI 基础 + VS Code 本地 + Multica 云端 | 前端开发资源分散 | 先 CLI + REST 稳定，前端并行原型 |
| **产品定位: Worktree 双入口** | ✅ 合理 | FileSession 隶属 Worktree，与 Task Card 同级平行；正交解耦 | UI 入口并列展示复杂度 | 文档明确 UI/UX 要求，实装时分离关注点 |
| **动态交互: sakura 级菜单体验** | ✅ 合理 | 明确 8 类交互场景性能指标、安全三角区、容错半径、缓动曲线 | 实装复杂度高、需专用定位引擎 | Floating UI/Popper.js 成熟方案；验收用例可自动化 |

**结论**: 所有集成点均为**可选、正交、复用现有基础设施**，无破坏性变更。

## 5. 技术风险热点分析

| 热点 | 严重度 | 文档中是否已识别 | 缓解措施是否充分 | 补充建议 |
|------|--------|------------------|------------------|----------|
| **Git 仓库膨胀** | 🔴 高 | ✅ §9/§8 | ✅ LFS + 不进 Git + gc | 增加 `max_repo_size` 配置告警 |
| **并发冲突** | 🟡 中 | ✅ §9 | ⚠️ 乐观锁+语义合并 | Phase 1 先单文件单 session，Phase 4 再加并发 |

| **存储后端一致性** | 🟢 低 | ✅ §9 | ✅ Trait+迁移工具+测试 | Phase 1 只做 FS，SQLite 后续 |
| **大文件恢复性能** | 🟡 中 | ⚠️ 部分 | ⚠️ 目标 <2s 但无细化 | 增加 `context_builder` 增量加载基准测试 |

## 6. 缺口与待补项

| 缺口 | 影响范围 | 优先级 | 建议处理 |
|------|----------|--------|----------|
| **Windows 路径长度限制** (260 字符) | Phase 1 目录创建 | P0 | 目录名使用 `blake3(file_path)[:12]` 缩短 |
| **Session 级锁机制细节** | 并发 checkpoint/恢复 | P1 | 文件锁 (`.lock`) + 乐观锁 (version 字段) 双重保护 |
| **Adapter 进程管理** (孤儿进程/僵尸进程) | Phase 2 spawn/attach | P1 | 复用 `domain-local-runtime` 的 `process_supervisor` + `graceful_shutdown` |
| **Transcript 存储格式选型** | Phase 3 | P1 | 对比 JSON Lines / MessagePack / Arrow，基准测试后定 |
| **Token 估算准确性** | 上下文预算控制 | P1 | 复用 `tiktoken-rs` 精确计数；预留 10% 缓冲 |
| **隐私规则扩展机制** | Phase 3 | P2 | `.star/privacy-rules.yaml` + 热重载 |
| **MR 导出模板引擎** | Phase 4 | P2 | Tera/Jinja2 模板，支持自定义 |
| **VS Code 扩展发布流程** | Phase 5 | P2 | 预留 `vscode-extension/` crate，后续单独仓库 |
| **OpenAPI 规范版本管理** | Phase 5 | P2 | `utoipa` 生成 + 破坏性变更只发 v2 |
