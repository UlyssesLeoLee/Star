## 3. Dependency order and parallel work

```text
WLD-0 Canonical binding
  └─ WLD-1 Worktree lifecycle / cleanup
       ├─ WLD-2 Task Card + CLI
       └─ WLD-5 Native Hook lifecycle enforcement
WLD-0 + WLD-2 ─ WLD-3 Schedule occurrence → Run saga
WLD-3 ─ WLD-4 Infrastructure admission/readiness
WLD-2 + WLD-3 + WLD-5 (+ WLD-4 infra facts) ─ WLD-6 Event / BI / Benchmark
WLD-0..WLD-6 ─ WLD-7 release and document closure
```

After WLD-0's binding contract is reviewed, WLD-1's lifecycle command model and WLD-5's visual Hook policy work may proceed in parallel on isolated worktrees. WLD-2 can split UI/session and owner/runtime work only after their shared RunContext and Task identity contracts are frozen. WLD-3 precedes any actual schedule execution; WLD-4 must finish before scheduled or Task execution can enter a running state. WLD-6 integrates the durable facts from those owners and must not use a shared cross-owner write transaction.

## 4. Global gates for every work package

- **Navigation/identity:** Project → Engineering Run → Worktree → Branch is canonical and does not depend on a remote host. A Run can exist without a Branch or Worktree; selecting a Run Worktree sets focus and reveals that Run's Apps.
- **Fail closed:** Missing identity, authorization, binding, provider, database state, profile digest, Hook decision, lease fence, capacity or readiness is a rejection/unknown state, never a successful fallback.
- **Owner boundaries:** Each domain commits its own state, audit and Outbox transaction; receivers commit their own Inbox/projection before ACK. Do not share cross-owner write transactions.
- **Resource bounds:** Preserve the two-record Multipass test cap (including Stopped/Deleted), Rust 1.99.0 baseline, bounded UI history/output/queues, cancellation/drain and measured memory/fairness gates.
- **Evidence discipline:** Distinguish source implementation, unit tests, isolated PostgreSQL fixtures, target DB/identity verification and live runtime acceptance. Report every gate separately; do not promote a partial/source slice to production-ready.
- **Product wording:** Use capability-neutral product language. Name a service provider only when that real connector is configured; avoid third-party comparison or imitation copy.

4. Continue WLD-3 Schedule and WLD-4 infrastructure in owner-separated phases; do not start a worker that can create an executing Run before confirmation and readiness.
