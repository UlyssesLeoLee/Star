Worktree 图谱、Canvas 与 Agent 关系

三块相对独立的子系统：worktree-canvas（14 个同级 crate）把 Git 现场变成可交互图谱； ARG（3 层）管 Agent 之间的关系与效果；Canvas/终端（4 个独立进程）提供实时协作与终端体验。 它们互相不直接依赖，只通过 facade 与 REST 交汇。

01 worktree-canvas · 14 个同级 crate

worktree-canvas 本身是 facade：只做 re-export，不含实现。真正的实现在 14 个 sibling crate 里。 外部只应 use worktree_canvas::*，不要绕过 facade 直接依赖某个 sibling。

数据流：从 git 事件到屏幕像素

为什么 debounce 是 100ms 而不是"实时"：git checkout 一次会产生上百个文件事件。 不过滤的话，图谱会疯狂重建，UI 卡死。100ms 是"合并一次操作"与"保持手感"之间的折中——这是性能约束，不是实现偷懒。

02 三个 WASM 桥 同一算法不写两遍

有些计算在服务端和浏览器都要跑（布局、查询解析、边校验）。做法不是"写两遍"，而是把 Rust 纯函数编译成 WASM 暴露给前端：

wasm layout-engine-wasm

暴露 pick_algorithm 与 visual_distance。前端本地试算布局，不等服务端往返。

wasm query-engine-wasm

暴露 parse_dsl / validate_dsl + 6 个关键字工具函数。输入框里实时提示语法错误。

wasm relationship-engine-wasm

暴露 edge_kind_count / edge_kind_at / validate_edge_kind。图例统计与边合法性校验本地完成。

收益：一致性由编译期保证，而不是靠"两边记得同步"。三个 crate 都是 cdylib + rlib 双输出—— 服务端继续用 rlib，浏览器用 cdylib，同一份源码。

03 ARG 三层 Agent Relationship Graph

ARG 回答"Agent 之间是什么关系、这次动作对别的 Agent 意味着什么"。分三层，单向依赖：

argData Tier · 40 .rs图数据与查询
本仓最厚的 domain crate 之一。存 Agent 关系图并提供查询能力。数据层不关心"关系要怎么用"，只关心关系本身。
▼
arg-bridgeBridge Tier · 14 .rs状态同步
四个组件：MemgraphEventListener（监听图变更）→ LangGraphStateUpdater（同步到 LangGraph 状态）→ PeriodFlushWorker（周期刷盘）→ OfflineQueue（离线补偿）。断线不丢数据。
▼
arg-effectEffect Tier · 20 .rs效果派发
五个引擎：ARGDispatchRouter（派发）· ARGContextInjector（上下文注入）· ARGTrustEngine（信任度）· ARGOutputEvaluator（输出评估）· ARGAchievementEngine（成就）。另含 10 套 challenges prompt + 8 拓扑 Cypher。
跨域边必须带 consults：ARG 触碰其他 domain 的边时，强制要求声明 consults（咨询了谁）。 目的是让"A 域为什么能读 B 域的数据"在代码里可查，而不是靠口头约定。

05 终端栈与凭证库

13 .rs terminal-stack

数据层实现：ScrollbackBuffer（环形缓冲，防无界内存增长）+ SplitTree（分屏树结构）。 MVP v0 = 内存 + JSON 序列化；持久化与前端 UI 留 P1 followup。

配套 terminal-protocol：OSC 52（剪贴板）+ Kitty Keyboard Protocol。 协议层与终端栈选型解耦，OSC 解析复用既有实现。

3 .rs ai-vault

桌面端索引控制：SearchPolicy + clear_search_index。 MVP v0 = local-only settings + 幂等清空。

相关：star-credential 走"用户设置 UI 自填 → KMS 加密存储 → 运行时解密"， 密钥不经环境变量（守门 #5 env 安全硬约束）。
